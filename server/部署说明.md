# 服务器端转写服务 · 部署说明

目标：手机 App 录完音，POST 到服务器，服务器用 faster-whisper 转成文字返回。

推荐形态：后端只监听 `127.0.0.1:8787`，由 nginx 反代到公网（例如 `/stt/`），这样只开 80/443 一个口，云服务器安全组也不用额外放行。

## 一、环境

- Linux（Ubuntu/Debian/CentOS 都行），Python 3.9+
- 内存 ≥ 1GB（small.en int8 推理约 500MB）
- 磁盘 ≥ 1GB（模型 464MB）

## 二、装依赖

```bash
# 建议先建虚拟环境
python3 -m venv /opt/podcast-venv
source /opt/podcast-venv/bin/activate

pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

首次启动会自动从 hf-mirror.com 下载 small.en 模型（464MB）到 `模型/` 目录。

## 三、启动

```bash
export API_TOKEN='换成你自己的长口令'
python3 transcribe_server.py
```

默认监听 `0.0.0.0:8787`。改端口用 `PORT=9000`。

自测：

```bash
curl http://127.0.0.1:8787/api/health
# {"model":"small.en","ok":true,"uptime":3.1}

curl -X POST http://127.0.0.1:8787/api/transcribe \
  -H "X-Token: 你的口令" \
  -F "audio=@test.mp3" -F "lang=en"
# {"duration":6.2,"elapsed":3.1,"text":"...","segments":[{"start":0.0,"end":3.2,"text":"..."},...]}
```

`segments` 是逐句时间轴，App 播放页用它做「点哪句从哪句播」；只返回 `text` 的旧代码也能用，App 会退回按句子切分（仍可复制）。

## 四、常驻运行（systemd）

```bash
sudo tee /etc/systemd/system/podcast-transcribe.service > /dev/null <<'EOF'
[Unit]
Description=Podcast Transcribe Service
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/podcast-server
Environment=API_TOKEN=换成你自己的长口令
Environment=PORT=8787
ExecStart=/opt/podcast-venv/bin/python3 /opt/podcast-server/transcribe_server.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now podcast-transcribe
sudo systemctl status podcast-transcribe
```

## 五、放行端口

如果直接暴露 8787：

```bash
# ufw
sudo ufw allow 8787/tcp

# 或 firewalld
sudo firewall-cmd --add-port=8787/tcp --permanent && sudo firewall-cmd --reload
```

**阿里云/腾讯云控制台的安全组也要放行对应端口**，只开服务器防火墙不够。

更推荐用 nginx 反代（只开 80/443）：

```nginx
location /stt/ {
    proxy_pass http://127.0.0.1:8787/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 600s;
    proxy_send_timeout 600s;
    client_max_body_size 80m;
}
```

此时 App 里的服务器地址填 `http://你的域名/stt`。

## 六、安全提醒

- 这是明文 HTTP，口令和数据都在公网上裸奔。**API_TOKEN 一定要设**，别用短口令。
- 更稳的做法：nginx 反代 + HTTPS（你有域名的话），或者干脆只在内网/自己 Wi-Fi 用。
- 服务只监听 8787 这一个口，别把整台服务器暴露。

## 七、换模型

```bash
WHISPER_MODEL=medium.en python3 transcribe_server.py
```

中文用 `WHISPER_MODEL=small`（不带 .en），请求时 `lang=zh`。

## 八、站点强制 HTTPS 的坑（POST 被 301 改成 GET）

如果 nginx 在 80 端口的 `server { }` 里写了整站跳转：

```nginx
server {
    listen 80;
    server_name 你的域名;
    return 301 https://$host$request_uri;   # ← 问题在这
}
```

那么 `/stt/` 也会被 301。浏览器的 fetch/XHR 跟随 301 时会把 **POST 改成 GET**：

```
POST http://你的域名/stt/api/transcribe
  → 301（方法丢失）
  → GET  https://你的域名/stt/api/transcribe
  → 405 Method Not Allowed
```

App 里表现为「转写失败：服务器 405」。**修复：让转写路径在 80 端口直连、不跳转。**

```nginx
server {
    listen 80;
    server_name 你的域名;

    # 转写接口：不跳 HTTPS，直接反代
    location ^~ /stt/ {
        proxy_pass http://127.0.0.1:8787/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 80m;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }

    # 其它路径照旧跳 HTTPS（原来 server 级的 return 挪到这里）
    location / {
        return 301 https://$host$request_uri;
    }
}
```

`location` 比 `location /` 先匹配，所以 `/stt/` 不会再被 301。改完：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

验证（不应再出现 301）：

```bash
curl -si -X POST http://你的域名/stt/api/health | head -3     # HTTP/1.1 200
```

> App v1.3 自身也会在 http / https 两套入口之间自动回退重试，但根治还是按上面把服务端配好。
